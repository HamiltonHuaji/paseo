# Skill 仓库同步需求

状态：已实现，设置按客户端访问能力与 daemon 订阅分层。本功能扩展 fork 的 [SKILL-01](fork-overlay-inventory.md#skill-01--保留手动安装的-skill)，不改变现有 bundled orchestration skills 的来源和选择机制。

面向 agent 的 [bundled skill](../skills/paseo-skill-repositories/SKILL.md) 与 [工具接口](../skills/paseo-skill-repositories/references/interface.md) 保存在仓库根目录的 `skills/`，沿用现有 bundled skill 发布机制。旧 daemon 未提供工具时，skill 要明确报告不能通过 Paseo 远端取得或发布。

## 目标与边界

一个 Git 仓库代表一组 skill。仓库中每个一级子目录是一个 skill，目录内有 `SKILL.md`；根目录可以有普通文件。增加或删除一级子目录，分别增加或删除这组素材中的 skill。一个 daemon 可以订阅多个仓库，同一仓库也可以被多个 daemon 订阅。

每个订阅在 daemon 上有独立、持久的普通 Git checkout。至少支持私有 GitHub 仓库。仓库访问仍由具备凭证的客户端完成；daemon 可以在无仓库访问能力、无客户端在线时对已初始化的 checkout 创建本地 Git commit。客户端负责搬运 Git 提交和远端引用，并用本机已有的凭证访问仓库。凭证不发送给 daemon。daemon 彼此之间没有连接、成员名单或发现机制。

订阅只引入素材。`~/.agents/skills/` 可以同时包含指向这些 checkout 中 skill 目录的软链接、Paseo 自带 skill 和本机零散 skill。agent 自行创建、修改和移除软链接；仓库同步不扫描、创建、修复或删除这些链接。已有链接会自然看到目标目录的更新。新一级子目录进入 checkout 后，是否建立链接由 agent 决定；远端删除目标目录后，悬空链接也由 agent 处理。不同仓库包含同名 skill 不构成同步冲突。

仓库 checkout 与现有 bundled skill 管理器分别拥有自己的文件。bundled skill 的显式卸载或选择变更即使移除了指向 checkout 的链接，也不得删除 checkout 中的内容。未订阅的本机 skill 继续受 SKILL-01 保护。

## 本地工作流

agent 可以直接编辑 checkout，也可以沿自己维护的软链接编辑。完成 skill 文件工作后，agent 显式选择仓库，查看 Git 状态，提交更改并请求发布。新增 skill 也按该流程在仓库 checkout 中创建一级子目录。同步功能不通过文件监听猜测编辑何时完成，也不自动创建本地提交。

提交先在 daemon 上完成，立即返回本地 commit ID 和上传状态。没有合格客户端时，结果是“已本地提交、尚未上传”，不会等待客户端上线。后续合格客户端连接时继续发布；断线或重试不得创建重复提交。首次订阅尚未取得仓库历史时，需要合格客户端完成初始化，之后才能以该历史为基础离线提交。

客户端可以把本地提交送到仓库。如果远端已前进，使用 Git 的提交重放、合并和非快进规则。能够无冲突重放的提交可以由客户端上传，并把最终提交链送回 daemon；发生冲突时保留本地提交和远端历史，交给 daemon 上的 agent 解决。自动流程不强推，不把失败的发布报告为成功。agent 能查看 Git 状态、差异、未上传提交和冲突，并在本地 checkout 中用 Git 继续、放弃或重试操作。

由 Electron 桌面客户端使用本机 Git 和现有凭证执行代办。网页与移动客户端可以保存、导入、导出计划，并为可连接的 daemon 配置订阅；它们不登记 Git 代办能力。持续连接的桌面客户端每五分钟补查一次远端，重连与计划变更时立即补查。

agent 可以主动请求取得远端更新。合格客户端负责访问仓库并送回远端提交；daemon 上的 agent 随后使用 Git 解决需要人工处理的合并或变基。请求时没有合格客户端，应立即报告远端不可用，不假装已经拉到最新版本，也不无限等待。

daemon 与客户端之间传递足以保留 Git 提交、父提交、树和引用的数据。可以使用 Git bundle 等离线传输形式；不在 Paseo 协议里另造文件级 diff、合并算法或完整 Git 远程协议。首版覆盖普通 Git 对象；Git LFS 和 submodule 需要单独的传输设计。

## 自动接收远端更新

每个“daemon × 仓库”订阅有一个自动接收模式。模式作用于该仓库的 checkout，不管理 `~/.agents/skills/`。客户端有访问能力且连接到该 daemon 时，检查远端并应用该模式；重连后补查错过的更新。发布本地提交独立于自动接收模式。

| 模式          | 行为                                                                                                                                                |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `overwrite`   | 取得远端版本并将 checkout 重置到远端提交，覆盖本地文件和当前分支状态。被取代的未上传提交保留在可恢复的 Git 引用中，不再自动上传，也不标记为已发布。 |
| `fastforward` | 只有 Git 可以快进并安全更新工作目录时才自动应用。分叉或本地文件阻碍更新时保持现场，报告给 agent 处理。已有本地提交领先远端时继续保留，等待发布。    |
| `none`        | 不自动取得或应用远端版本。只在用户或 agent 主动请求时取得远端引用，不自动应用；本地提交仍可请求发布。                                               |

模式不改变 Git 的提交历史规则。`overwrite` 是用户明确选择的破坏性工作目录策略；`fastforward` 和 agent 主动拉取保留 Git 对冲突的判断。远端仓库被强制改写或目标分支消失时，停止自动应用并显示异常，等待 agent 或用户明确决定新的基线。

agent 明确接受远端强制改写时，可用 `fetch_skill_repository` 的 `allowRewrite` 选项取得新引用。旧远端引用先存入本地恢复引用；此操作不改变本地工作树或当前分支。

## 设置与状态

全局设置的「Skill 仓库」管理本设备知道的仓库、Git 代办权限以及计划导入导出。代办权限为不代办、读取、读取并发布；导入计划和从 daemon 读回配置都不自动授予本机代办权限。仓库表单在添加或编辑时打开，导入先预览，再对冲突逐项选择保留本机或导入版本；未选择的冲突不会导致部分导入。

每个主机设置中的「Skill 仓库」管理该 daemon 的订阅、自动接收策略和 agent 发布授权。仓库行提供手动操作、同步状态与策略说明；说明支持桌面 hover 和移动端点击。`overwrite` 与 `fastforward` 的「立即同步」取得远端并按当前策略更新 checkout；`none` 的「获取更新」只取得引用，由 agent 决定如何合并。手动操作不创建本地 commit，也不改变自动接收设置。

列表来自 daemon 持久保存的实际订阅；客户端的待应用计划单独标明，不能将本地空计划显示为 daemon 没有订阅。离线时显示本机保存的订阅；读取失败、仍在加载、成功读到空列表分别呈现。Git 状态包括工作树、本地与远端提交差距、待发布状态、上次检查远端的时间和可用代办客户端。界面只将本地提交与上次取得的远端比较，不将缓存状态称为远端最新状态。checkout 路径与提交引用在详情中查看，保存操作不需要滚动经过这些信息。

设置与手动操作使用 `skills.repository.get_state`、`skills.repository.configure` 与 `skills.repository.sync` RPC。新设置页通过 `server_info.features.skillRepositoryManagement` 判断主机支持，旧消息保持兼容。agent 的 fetch/publish 接口与 Git 工作流保持原样。

## 客户端代办与权限

让 agent 请求发布，等价于允许它借有凭证客户端的能力写入指定仓库和分支。同步计划要明确授权哪些 daemon 可由 agent 发起发布。客户端只代办已配置仓库的取得与发布操作，不接受 daemon 指定任意远端地址、分支或 Git 命令。客户端根据自身实际能力为每个计划登记可执行的读取和发布操作；没有凭证或无法访问该仓库的客户端不登记。登记绑定到当前认证连接，断线即失效。

daemon 从接受 agent 创建或本轮指令的认证连接记录来源，记录为该连接的 principal 与客户端标识；无法确定来源时记录空值。来源关联到该轮运行及由它启动的子 agent，由 daemon 在每次 agent 工具调用的内部上下文中继续传递。需要经过 CLI 子进程时，可以把来源作为可空的逐次调用环境信息传入；它只用于定位原始 turn，daemon 仍以自己记录的来源为准。agent 不能在工具参数或环境变量中自报来源，创建 agent 的客户端也不能永久替代本轮来源。重试同一指令不得改写首次接受时的来源。定时任务、CLI 已断线后的运行等可以没有当前来源。agent 进程可能跨 turn 复用，不得把本轮来源固化在会话启动环境或写入全局进程环境。

代办请求优先给本轮来源客户端，前提是它仍在线且登记了对应仓库和操作；否则从其他合格客户端选一个。来源只影响路由，不授予仓库权限。一个请求只交给一个活跃执行者；重连、多个窗口和多个客户端的重复处理按请求及 Git 提交身份去重。没有执行者时，本地提交保持可恢复的未上传状态，主动拉取则立即报告不可用。

## 多设备配置

同步计划用稳定 ID 标识仓库和成员，记录仓库地址、目标分支、daemon 的 `serverId`、每个订阅的自动接收模式及 agent 发布授权。daemon 持久保存自己的订阅和 checkout 状态，因此客户端全部离线时，agent 仍知道应向哪个本地仓库提交。客户端保存完整计划视图，以及本设备的 host 连接和仓库执行能力。连接时读回 daemon 的订阅，补回本机缺失的仓库记录；已应用计划不会在重连时反复覆盖 daemon。显式修改和导入产生待应用配置，应用时与本机之前看到的 daemon 配置比较；其它客户端已经修改或删除时，保留当前 daemon 配置并显示待处理项。用户可以重新查看并保存，或采用主机配置。

客户端可以导出和导入版本化的同步计划。导出包括所有已知 daemon 成员，即使本客户端无法连接其中一些；不包括 Git 凭证、Paseo 连接凭证、客户端 checkout 或设备本地路径。导入后，无法连接的成员保持在计划中并标为“本设备未配置连接”，不触发操作，也不被当成同步失败。客户端 A 只连接 daemon A、客户端 B 只连接 daemon B 时，两者可以通过同一个仓库分别完成各自可达部分的工作。

导入按稳定 ID 合并，不以导入文件中缺少某个成员来删除本机已有成员。显式移除需要可传播的删除记录；同一计划的仓库、分支或订阅模式出现并发修改时报告配置冲突，不让最后导入的文件静默覆盖。多个客户端同时在线时，daemon 对同一仓库的 Git 操作串行化；只有完成 Git 结果回传后才更新发布或接收状态。

## 验收场景

- agent 完成 skill 编辑并本地提交时，所有客户端都离线；它立即得到 commit ID 和“尚未上传”，有凭证的客户端上线后可发布该提交。
- 客户端 A 只认识 daemon A，客户端 B 只认识 daemon B。A 代 A 上传后，B 从仓库取得提交并按 B 的模式更新 checkout；任何 daemon 都不知道另一台 daemon。
- 同一 daemon 订阅两个含同名一级子目录的仓库。两个 checkout 都保持完整，`~/.agents/skills/` 的链接保持 agent 原先的选择。
- `overwrite` 用远端版本替换有本地改动的 checkout，未上传的本地提交仍可恢复；它不会触摸 `~/.agents/skills/` 的链接或其他仓库的 checkout。
- `fastforward` 遇到分叉时保留本地文件和提交。agent 主动取得远端后能在 daemon 上解决冲突，再提交并发布。
- `none` 在客户端上线、远端前进时不改动 checkout；用户或 agent 主动请求后才取得远端引用。
- 新客户端没有本地计划，但所连接的 daemon 已保存订阅；主机页显示实际订阅，全局仓库目录补回对应记录，本机代办权限保持关闭。
- 客户端 A 保存策略后，客户端 B 重连不会重新应用旧策略；B 持有旧配置时提交修改会显示冲突。
- 导入包含未配置 host 的计划后，本客户端保留其成员记录；不会尝试连接该 host，也不会删除其他客户端负责的订阅。
