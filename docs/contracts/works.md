# Paseo Works 行为契约

Works 让用户找到工作、相关会话、进展和成果。记录随项目持久保存，临时代码
checkout 的释放不影响工作记录及保留的成果。接口细节见
[v2 模块参考](../refactors/work-objects-v2.md)，v1 见 [Experiments](../experiments.md)。

## WORKS-01 — 独立工作对象与组件语义

Card 表达领域或成果，Item 表达其中一次执行或具体交付。Topic/Experiment 和
Issue/Attempt 是预设，所有合法组合可用。标题和正文完整可读；创建后身份、
Item 的父 Card 与 storage 归属稳定，改名、修改 label 不改变这些身份。

组件按需存在，MCP、CLI、RPC 与客户端行为一致：省略字段保留原值，显式移除
有确定效果，各组件的追加、删除或整体替换遵守已公布的接口语义。
Config 的局部修改不会被调用者误认为服务端会自动合并。

自动 touches 与显式 Sessions 分开；完成与归档分开；实际起止时间与记录活动
时间分开。读取不伪造工作进展，失败的执行也能作为已结束的结果保存。
关联会话和创建对象本身不启动 agent、作业或 worktree。

验收：跨接口创建、读回、修改和重连后身份与内容一致；组件删除、Result 重开、
label 修改和归档恢复不会串改其他组件或删除成果。v1/v2 同时存在时互不改写。

## WORKS-02 — 可复用成果来源与本地 W&B

用户能将资源挂载、数据来源与面向用户的入口分别配置。Card/Item 的继承与
显式来源引用解析到正确对象；使用继承配置不会读到来源对象的私有输出。
空配置、移除配置和继承有可区分的结果。

本地 W&B 的指标、摘要和可用 artifacts 可从实际本地记录读取。续跑、多文件和
多 run 可以辨认；缺失记录或内容给出明确原因。正常追加与来源替换不会混淆，
summary/latest 反映原始数据，不从展示降采样结果反推。
使用此能力无需另启 Python 或完整 W&B 服务，云端 W&B 不在本条范围。

验收：同一来源供多个 Item 使用、续跑引用同一 run、切换 run、文件追加与替换、
artifact 缺失均可观察到正确内容；数据源上下文和用户入口不串到其他对象。
Viewer 访问遵守[Viewer 契约](viewers.md)。

## WORKS-03 — 可解释的进度观察

日志、命令和共享 viewer 数据来源可按明确计划展示多单位进度。
只对已定义的区间进行换算；未知、错误、不定总量、达到总量与实际结束可区分。
结束有来源证据；同一 W&B run 的结束不自动完成每个引用它的 Item。

可见页面共享有效观察，隐藏或断开后停止该页面驱动的刷新。
观察失败保留最后有效值及其时间，不能伪装为新进展；来源改变后不混入旧观察。
客户端刷新不意味着后台作业已受监督。

验收：并行 Item、暂时读取失败、重连、来源替换、到达总量但没有结束证据时
均显示正确状态；重新读取同一记录不会增加工作活动或虚构结束时间。

## WORKS-04 — Canvas 与连续详情

Card 默认提供摘要，用户可逐 Card 选择曲线。Item 按顺序连续展示、各自展开；
详情有合适的滚动容器，不挤走工作区 tabs。Goal、来源关系和用户布局可持久恢复，
自动数据更新不覆盖手动位置。

曲线读数对应实际采样点，可隐藏系列和选择对数轴。空、未配置、加载、错误与离线
状态可区分，来源入口打开正确对象。排列和撤销的用户行为与 EXP-04 一致。

验收：长 Item 列表、多曲线、并行工作和离线恢复可用；切换工作区、v1 与 Works
后保留各自导航状态，详情滚动不移动 Canvas。

## WORKS-05 — Agent 工作有归属和可访问成果

`paseo-works` 指引 agent 先查已有相关工作，同一开发交付继续同一 Issue；
新实验运行、重试和续跑分别保留 Attempt，即使复用一个 W&B run。
是否登记由用户工作成果决定，普通咨询不因调用工具而强制登记。

每次交付能找到成果入口、实际代码版本、输入、执行与结果。输出放在已取得的
storage 或用户指定位置并登记；用户入口只列可查看的结果。
工作区由 Git 管理并与并行修改隔离；清理 checkout 后必要结果与代码仍可恢复。

验收：另一 agent 能继续同一问题、找到旧执行和成果；失败与重试不会覆盖旧证据。
链接会话、touch、记录完成均不自动授权委派或启动操作。工具缺失时明确报告限制，
不伪造保存成功、不把 v2 调用写进 v1。实际 skill 边界见
[paseo-works](../../skills/paseo-works/SKILL.zh-CN.md)。

## EXP-01 — v1 数据与入口连续可用

v1 Experiment/Attempt 保留各自身份、关系、结果、时间与输出归属。
同一项目的不同工作区可访问既有记录。Works v2 的发布不迁移、覆盖或双写 v1。

验收：升级前的 v1 项目在升级后可通过原有 CLI、MCP 和客户端读取与继续使用；
旧成果入口仍有效。未实现的 Goal 管理、doctor/repair 和 post-turn reporting
不记作已交付。

## EXP-02 — v1 进度与并行执行

多单位进度只覆盖显式定义的区间，未知、错误、indeterminate 与 ended 可区分。
并行 Attempt 各自可查看，可见页面共享观察，隐藏后停止页面驱动的刷新。

验收：多个未结束 Attempt、读取失败与切换页面时不会把某次执行的进度或结束状态
套用到其他执行，也不会把缺少数据解释为零进度。

## EXP-03 — v1 导航与完整执行历史

Experiment 页面保留工作区 tab 状态与完整 Attempt 历史，各 Attempt 可独立展开。
桌面详情独立滚动；Android 返回先关闭详情，再按页面导航返回。

验收：从工作区进入、查看长详情、返回和重连后，工作区 tabs 与 Attempt 顺序不丢失，
滚动详情不拖动整个 Canvas。

## EXP-04 — 可持久操作的无界 Canvas

画布可平移、缩放、拖动和调整卡片大小，不受已有内容范围限制。
位置持久化，Arrange 按来源关系给出可复现布局，用户可一步 Undo；
刷新不覆盖手动布局。

验收：指针跨卡片或离开起始区域仍只完成一次操作；Arrange 后 Undo 恢复原位置，
刷新、重开后保留用户布局。
