# 网络出口与身份上下文

本契约约束 Paseo 自身及其内置功能发起的网络访问。用量、账号发现、模型发现、
语音、更新、插件目录、推送、Hub、relay 和派生连接均在范围内。
第三方程序由 Paseo 启动时，配置传递也在范围内。
它不授权重写 Viewer 传输、改变凭证所有权或增加逐请求审批。
当前缺口见[网络出口审计](reviews/network-egress-2026-10-30.md)。

## NET-01 — 外发请求遵守其有效网络出口配置

用户为请求执行环境配置的代理和直连例外，对该环境内所有适用请求生效。
前台操作、后台刷新、首次发现、重试、重定向、HTTP(S) 和 WebSocket
具有一致的出口语义；能正常返回数据不能代替代理已生效的证据。

daemon/CLI 的 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 及小写形式，
桌面客户端的系统代理，以及 provider 的会话级设置，都按各自作用域解释。
`ALL_PROXY`、代理协议、大小写冲突和平台代理来源的支持范围及优先级可查明；
无法执行已选代理配置时适用 NET-04，不能忽略后直连。
Windows 系统代理不因一项功能转入桌面主进程便失效。

每次请求按目标判断直连例外；重定向后的目标也受约束。
Unix socket、进程间通信和明确的本机服务保持本地可用，不把本机认证送到外部代理。
远端服务不会仅因为叫作 host、viewer 或 tunnel 就自动获得直连例外。

Paseo 的 direct/relay 连接方式与出站代理是两个维度。选择 relay 后，连接 relay
服务器仍遵守执行机器的出口配置；选择 direct 不表示忽略 HTTP 代理。
客户端代理配置不自动授权它代替远端 daemon 访问提供商；跨机执行与代理权限
仍遵守 [SKILL-02/03](skills.md) 和 [VIEWER-02](viewers.md)。

## NET-02 — 辅助功能保留身份、服务和网络上下文

Paseo 代表某个会话或账号读取用量、发现模型、查询账号资料或调用远端工具时，
使用该操作所属的有效身份、目标服务和网络配置。读取凭证文件不等于恢复了完整上下文。
不同会话即使使用相同账号或凭证文件，也能保留各自的出口和服务设置。

自定义 API 地址与正向代理分别处理。自定义服务不提供用量接口时，结果明确显示
不可用或保留标识清楚的缓存；不因此绕回官方服务。官方账号自身的用量查询可以
使用独立配置，但不能从另一会话的凭证或失败结果推断这项配置。
host 级账号列表也受身份与出口约束，不因缺少 agent ID 就获得隐含的直连许可。

凭证只发送到其所属或用户配置授权的服务。包含多个主机的凭证库保留主机归属，
企业 GitHub 的凭证不会因为排在文件前面就被发送给 github.com。
代理认证和目标服务认证各守其作用域，重定向与重试不扩大范围。

## NET-03 — 进程、连接和缓存边界不改变有效配置

从 daemon 到插件/worker、从客户端主连接到 Viewer 等派生连接、从业务层到 SDK
或子进程，操作的有效网络配置仍然成立。不得把“环境变量已经传递”或“主连接
已经成功”当作另一网络栈也遵守配置的证据。

并发会话、连接池、账号合并、请求去重和凭证候选重试不串用网络上下文。
配置变更生效后新发起的请求、重连和新建子进程使用新的配置；不为一次请求临时
改变其它会话的网络行为。旧缓存可以继续展示并标明来源/时效，但不能掩盖新的
外发请求仍使用旧上下文。

继承的环境、会话覆盖和用户工具自身配置保持有效。修复一个 Node 调用点不能
代替对 Electron、Web/native、第三方 SDK 和实际子进程边界的核对。

## NET-04 — 代理失败可见且不扩大网络权限

代理不可达、认证失败、配置不支持或必要上下文缺失时，操作给出有界失败并允许
重试/取消；不能为了获取用量、恢复连接或完成下载而悄悄改走未获配置允许的直连。
配置中明确允许的直连规则仍然有效。

诊断能区分请求由哪台机器、哪个功能发起，目标服务是什么，以及选择了哪类出口。
日志与普通客户端状态不暴露 token、代理密码或完整含密钥 URL。用量读取失败
不修改原有凭证，不阻塞已经可用的会话主路径。

## 当前提供商 HTTP 出口的配置

用量、Claude 账号资料和云端语音支持 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`
及小写形式。同名变量小写优先；协议专用变量优先于 `ALL_PROXY`；没有 HTTPS
代理时可复用 HTTP 代理。支持 HTTP/HTTPS 代理及代理认证。未支持的协议（包括
SOCKS）返回错误，不静默直连。`NO_PROXY` 支持主机、域名、可选端口和 `*`。

host 级用量和云端语音使用 daemon 环境；会话用量保留该 agent 的有效环境。
Codex/Claude 的独立模型目录属于 host/provider 作用域，使用该作用域配置，
不会从任意一个会话推断全局代理。只在 agent 上设置代理，不会为其它 host 级
后台任务配置代理；需要覆盖这些请求时，在 daemon/provider 环境设置代理。

## 验收项目

以下定义行为场景，不指定代理库、全局 dispatcher 或独立网络服务等实现。
临时执行脚本、假凭证、证书和流量记录放在工作记录 storage，允许复用，不进入 Git，
也不自动扩大 [RELEASE-02](distribution.md#release-02--验证范围与发行解耦) 的检查范围。

| 场景                                                            | 观察结果                                                   |
| --------------------------------------------------------------- | ---------------------------------------------------------- |
| 本地假目标、记录流量的代理；分别发 HTTP、HTTPS、WS、WSS         | 应代理的请求只经过指定代理；目标仍可直连时也不能漏走       |
| 大小写环境变量、`NO_PROXY` 精确主机/端口/域名规则、配置来源冲突 | 按支持并说明的语义选路；例外不会扩展到其它目标             |
| 代理拒绝、断开、认证失败、不支持的代理配置                      | 目标没有收到额外直连；错误可识别，取消结束网络活动         |
| 两个会话共用假凭证但采用不同出口；会话与 host 级用量并发        | 发现、资料查询、首次读取、强制刷新及重试各自保留上下文     |
| 自定义 provider 地址与仅含企业主机的凭证库                      | 不向默认官方地址或错误主机发送凭证；不支持的用量明确可见   |
| daemon → 插件/worker；父进程以环境或启动参数配置代理            | 子进程实际访问符合配置；只核对 env 内容不算通过            |
| 桌面系统代理下主连接、Viewer 派生连接、更新下载                 | 都符合所属代理策略；Viewer URL、身份和跨版本行为符合原契约 |
| CLI、Connected Hosts、relay、Hub；远端 HTTP/SSE MCP             | 相同有效配置覆盖 HTTP 与长连接，重连不改变出口             |
| 保留连接/缓存后改变代理；同账号多会话交错执行                   | 新外发请求遵守新上下文，另一个会话不被改写                 |
| 本机服务、Unix socket、OpenCode 本地桥、Viewer 本地 listener    | 本地通信继续工作，本机服务凭证不被转发给外部代理           |

使用隔离环境和假凭证完成检查。网络层探针与产品调用链检查分别记录；一个运行时
的代理探针通过，不代表所有功能或 Windows/Android/iOS 设备已验收。
