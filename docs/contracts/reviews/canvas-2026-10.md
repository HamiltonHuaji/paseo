# 2026-10 Canvas 第一轮迭代

基线：`fdbde3677614983bb2946e84c36cef1e8d5d4926`，官方 v0.13.0-beta.1 加 fork 会话等迁移。
质量要求见 [Canvas 契约](../canvas.md)。用户要求开放迭代，并明确旧算法与
左到右方向不构成需求。

## 选择依据

先以来源识别、关系追踪、可读文字大小下的移动成本和空间记忆评价候选。
比较旧折返、关系分层和纵向关系分层。第一版强制单向展开把五卡直链拉得更宽，
因此本轮保留分支分区，允许无分支长链折返，并将独立图块放在同一行。

横向分层是本轮选择，未写进永久契约。Paseo v1 的纵向候选概览稍好；
其他真实图未显示同一方向的普遍优势。后续可以修改方向、组件分区和布局策略，
只要仍按上述阅读任务评价。

会话 surface 的当前控件明确声明按事件时间排序且时间从上到下。
本轮保留该功能的语义，更新它所使用的共享路由；这不把纵向时间排列变成
其它画布的要求。新的共享重排在真实 v1/v2 拓扑对照页展示。

## 保留的问题

- driveinfinity v1 的分叉长图仍偏宽。概览比例改善很小；长链与分支的局部分区仍有改进空间。
- 多条边可以共享通道或交叉，尚未进行全图交叉最小化与通道分配。
- 人工重叠、卡片相贴或出口被堵住时，当前路由不能保证找到可用绕行。
- 未验证原生设备上的触摸与绘制性能；浏览器通过不替代原生验收。
