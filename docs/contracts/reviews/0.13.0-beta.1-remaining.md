## 项目存储与有效配置

项目模式的开启方式归[自定义 provider 文档](../../custom-providers.md)。项目 home
属于 Git common directory；handle 保留存储归属，cwd/worktree 的变化不隐式迁移会话。
旧无标记 handle 继续使用原全局 home，用户 auth/config/skills 的所有权不变。

真实 Codex 0.162.1 使用隔离 home、本地 Responses 和两个独立 Git 项目：
Astra/xhigh/priority 与 Sol/high/default 的目录默认值、实际请求、显式选择、配置实时
变更与重启均核对。两个项目分别完成普通导入/继续、原生分叉、writer 存在时复制、
rewind 新身份、归档、只读历史和恢复；sibling worktree 能发现会话，另一项目不会串入。
移除临时 worktree 后历史可读；共享 skill 的实际内容进入两项目请求，用户内容保持原样。
项目模式没有向用户 home 新建 sessions 目录。

本轮修复默认模型未进入 collaborationMode 请求、选择意图丢失、祖先配置缓存未失效、
未声明的 effort 被展示为能力以及非法 tier/effort 静默降级。失效选择现在给出可处理错误；
未知自定义模型交给原生 provider 校验，不新增客户端模型白名单。
完整双项目原生文件 2 项通过，features 46 项、目录 1 项及既有选择/导入定向通过。

旧全局记录能发现并原地导入。**Codex 0.162.1 的跨 home fork 仍受原生限制**：
有效外部 rollout path 与源 UUID 也返回 no rollout found。候选说明原因并建议原地导入，
不移动/改写原生数据库；回归验证失败后源仍可读、没有 copy-only 内容。
`context-legacy-diagnose.json`、`native-path-variants.json` 保留实际参数和原生失败。
这不是项目内副本失败，也不是旧全局迁移成功的证据。Windows 链接仍缺运行验证。

## 会话恢复、状态与只读历史

分项结果归[会话报告](0.13.0-beta.1-sessions.md)。真实 105-turn 来源在继续执行时，
可从第一个已完成工具边界 fork；分支重启继续包含该工具上下文且没有后续来源内容。
原生 fork 返回后、manager 提交前强杀隔离进程，新 manager 仍能读取稳定身份和持久
rewind intent，重试与再次 rewind 保留两条关系记录。定向持久失败测试覆盖其他窗口。

Closed/archived 105-turn 历史读取、缺失历史失败均不取得交互 writer，不改变原生
JSONL 哈希或归档位置；读取对象存活时仍能原生 archive，后续显式交互恢复成功。
单次 provider 测量：较早边界 fork 408 ms，closed/archived read 476/465 ms，
缺失历史失败 365 ms，显式 resume 623 ms。它们不是浏览器首屏或性能保证。

随后实际浏览器发现另一层回归：manager 把历史 reader 注册进活跃会话，使 closed 和
archived 记录变为 idle，虽然原生文件未变化。问题 `item_2fdcd410` 的修复使读取对象
在操作结束后关闭；历史 RPC、MCP activity、child 历史及清除未读标记不激活会话。
显式交互恢复 writer，closed 来源 fork 只创建分支 writer。冷启动恢复持久历史行和
child 时间线，重复分页保持 epoch。首次失败与后续通过证据分别保留，具体范围见会话报告。

最终 daemon `30dd460d0`、Web `f47c964dc` 的 Chromium 验收通过：三个独立冷路由
分别读取 closed、archived 和缺失历史，前后仍 closed，原生身份、归档位置及两个 home
的 JSONL 哈希不变。实际捕获 timeline read 和 clear attention，未发送执行/归档动作；
closed 未读标记清除，页面异常为 0。最新回复/错误可见后两帧的单次测量为
7,811 / 5,418 / 4,424 ms；不是全界面就绪或性能优化证明。后续独立只读检查
确认 Updating messages 和 composer Loading 消失（约 9,350 ms），没有激活会话。`30dd460d0` 同时保留
清除未读事件里的已知 runtime metadata，红绿事件断言归独立 receipt。

真实 child 的 held/completed/failed 分别保留自己的执行证据。父完成不会替 child
完成；历史只有 started/interacted 时显示 unknown。9 项 writer 故障检查通过，
包括关闭挂起/拒绝、取消超时和失败恢复；保留上游 closed/可重试语义。
自动恢复旧配置仍是未决定行为，没有擅自加入本次交付要求。

迟到异步回答原先在新 turn 接受前结案，失败会丢失可重试问题；现已修复。
15 项协议检查覆盖多问题、自由文本、重启、重试和竞态，4 项既有计划审批检查通过。
原生 0.162.1 的异步消息工具只暴露 message；实际消息和重启历史已验证，
结构化多问题仍只有协议级证据，不能声称全链路原生验收。

## 工具发现与中断恢复

MCP-01 关联 `item_1d1f6925`。旧生产 fork 在停止后执行 rewind，随后本会话缺少工具，
刷新后恢复；证据不支持把“单独停止”认定为根因。旧 rewind 未继承运行时 MCP，
候选复用官方 `827178df90843048a9c0e0658553e739d594d26f` 的修复。

真实 stdio MCP 服务验证新会话、下一 turn、停止后继续、rewind、关闭恢复五次调用。
临时移除配置传递的负对照在第四次失败，恢复候选后通过。后续原生矩阵补齐初始化中断、
独立 fork、来源继续、隔离 app-server 强杀后重连、发现失败后 reload、主动禁用、
重新启用和服务撤权。失败或禁用时没有伪造工具调用；恢复后服务计数与模型请求同时确认。

本轮还修复被忽略的原生 discovery 失败通知，使原因通过现有 warning 内容可见并提示
reload 重试。撤权验证使用实际本地 MCP 错误响应，不等于外部 OAuth 服务集成。
测试不调用生产 MCP 或线上模型，也不为历史浏览启动 writer。
负对照归 MCP issue storage；新增矩阵归 `session-closeout-evidence`。

现有 Ubuntu server CI 固定 Codex 0.162.1，先检查版本，再串行运行两份现有 Codex
local.e2e 文件及 persistence 文件中两项 `closed history` SDK 场景；
`scripts/ci-workflow.test.mjs` 的 13 项检查通过。没有新建 feature job，
没有触发远程 CI。
