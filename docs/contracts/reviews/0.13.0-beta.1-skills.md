## Integration

The old `4e22670cc`, `330c07d0d`, `55199f96b`, `96a02036e` and the Skills
parts of `4a908baee` are represented by the migrated module. Unrelated session
recovery and daemon-update hunks were excluded. Newer host routing, provider
configuration and canvas code remain on the target baseline.

Server service, protocol, client methods, permissions, MCP, desktop IPC, plan
persistence and settings are connected. `paseo skill-repository` exposes
`ls`, `inspect`, `configure <file>`, `sync` and `remove`; configuration and
removal use the same expected-subscription comparison as the UI. Git publication
remains an agent-scoped MCP operation and retains the subscription's grant.
The bundled `paseo-skill-repositories` guide is packaged by the existing server
build. Works owns the separate `paseo-works` and `track-experiments` content.

The ownership contract intentionally changes upstream tests that expected an
existing copy to be repaired from the bundle or duplicated into another root.
The tests now assert retention of the actual user bytes and links. Transaction
rollback and explicitly confirmed removal remain covered by the existing suite.
New installations retain the target baseline's canonical `.agents/skills` and
Claude destinations; they do not create a new `.codex/skills` copy. Existing
Codex copies are preserved under the same ownership rule.

New feature fields are optional. Added RPCs use dotted namespaces with request/
response suffixes. Client settings and the executor check
`skillRepositoryManagement`; older hosts require an update rather than an
alternative RPC path. Existing message fields and shapes were not narrowed.

## Verification and evidence

On integration source `f804a4d7889acf664fb825aa449c8334c7c5cb9c`, an isolated real daemon
sent Git fetch jobs over WebSocket to Electron 41.2.0. The sandboxed renderer invoked
the actual preload API and IPC handler against a local bare remote. Initial sync
applied the original skill. Disconnect removed executor capability and returned
`unavailable`; a new physical connection registered again and applied the next remote
commit. All four Git jobs succeeded. The fixture used no hosted repository or user
credentials; this does not verify hosted authentication or Electron 44.2.0.
Evidence: `item_a435ce98/root-closeout-evidence/skills-ipc-vUD6z5/proof.json`, with
the daemon and Electron logs alongside it.

- `npm run build:client` and `npm run build:server`: passed.
- Package typechecks for server, app, desktop and CLI: passed after rebuilding
  their owning declarations.
- `npm run lint`: no warnings or errors.
- `npm run format` and `git diff --check`: passed.
- Existing operations and controller suites: 37 and 43 tests passed, respectively.
- CLI `skill-repository --help`: displayed all five subcommands.
- Retained issue storage contains `verify-skill-repositories.mjs`,
  `git-fixture.log`, `verify-skill-plan.mjs`, `plan-browser.log`, test logs and
