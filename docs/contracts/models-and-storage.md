# 模型发现与项目存储契约

模型选择、执行和历史操作观察同一个有效配置上下文。
Provider 配置方式见[custom providers](../custom-providers.md)；会话行为见[会话契约](sessions.md)。

## CODEX-07 — 完整的动态模型能力

用户可选模型包含当前 provider 返回的全部可用页。推理档位、速度档位及
service tier 来自该模型声明的能力，名称与说明准确；新增模型不依赖客户端白名单。
已知的会话控件与当前选择在首次打开、daemon 重启和重连后仍可见，
不要求先发送消息才能出现。历史按需读取、目录刷新和会话恢复不把已知能力暂时清空。
显示控件不要求启动该会话的执行实例或全量读取历史。

验收：所选模型只存在于第二页或更后页时，仍可选且能力完整。
有相应 tier 的模型显示该选项，执行使用对应 tier 身份；无该能力时不提供误导开关。
目录读取失败不会显示成“没有模型”。
打开一个 daemon 重启后尚未运行的已有会话，先只读历史，再发送消息；
前后核对速度、Plan、权限模式及原有选择，并在读取和恢复过程中重连。

## MODEL-01 — 选择与执行的有效配置一致

模型目录、默认模型、推理档位、tier 和实际执行对应相同的 host、provider/profile、
项目与存储上下文。不同配置上下文不会复用错误的默认值或目录。
用户显式选择与“跟随 provider 默认”保持区别。

验收：两个项目采用不同 profile 或默认模型时，切换、重连、fork、reload 和 rewind
后仍各自正确。配置改变后界面反映新的有效能力；已有显式选择失效时给出可处理的
说明，不静默换成另一模型或 tier。

## STORAGE-01 — 项目级 Codex 会话与共享用户资源

本条约束可选的项目存储模式。候选版本的实现和验收范围见
[升级验收记录](reviews/0.13.0-beta.1.md)，不以官方 baseline 是否提供该能力代替验收。

项目的 Codex 会话、归档及其必要持久内容可存放在项目归属的存储中，不再随着
该项目的使用持续挤入默认 `~/.codex/` 会话目录。工作目录选择本身不代表存储归属。
同一项目的不同 Git worktree 能找到该项目会话；移除临时 worktree 不删除持久会话。
合法的长路径和非 ASCII 项目路径可持久保存，重启后可读取、更新和删除；
不同项目即使路径共享很长的前缀，也不串用记录。已有合法路径下的记录继续可用。

创建、继续、历史读取、fork、rewind、导入、归档恢复和模型发现都识别相同上下文。
重启后仍能找到原会话与分支关系。只移动一个数据库、设置历史文件大小或修改 cwd，
不能作为此目标已经满足的证据。

独立项目存储仍能使用用户授权的凭证和用户级 skills。会话数据归属与共享用户资源
分别可配置；隔离项目不会意外失去认证，也不会把密钥写进版本库、成果包或普通日志。
跨机器的凭证共享策略属于后续设计，不由本条授权。

验收：两个项目分别创建、重启、导入、fork、rewind、归档和恢复会话，目录发现与
实际执行一致，存储互不串用；删除其中一个临时 worktree 后记录仍可用。
启用共享 skills 后两个项目能使用它们，用户目录所有权仍符合
[SKILL-01](skills.md#skill-01--用户安装的-skills-保持用户所有)。

旧全局会话的保留、导入和迁移范围可见；失败或中断后原数据仍可恢复，分支来源
不丢失。启用项目存储不隐式搬走或删除已有 `~/.codex/` 数据。
