# Viewer 行为契约

Viewer 是用户检查成果的入口，资源来源由工作记录配置。
Works 的来源引用语义见 [WORKS-02](works.md#works-02--可复用成果来源与本地-wb)。

## VIEWER-01 — 稳定的资源与目录入口

v1 与 v2 各有可辨认的路由，使用同一 viewer host 时仍正确解析各自记录。
用户配置的监听端口优先；端口冲突有有界回退并公布实际地址，设置失败保留可用入口。

挂载目录新增文件后可浏览和打开，目录分页、范围请求和缓存响应准确。
重叠挂载选择最具体的合法路径；路径遍历被拒绝，错误响应不泄露实际文件系统路径。

验收：v1/v2 成果共存、持续产出新文件、重叠挂载、分页、端口冲突与配置失败时
均能定位正确资源，未知的 v2 路径不会误落到 v1 记录。

## VIEWER-02 — Direct/relay 下可持续使用的本地入口

同一 host 的本地 viewer origin 可稳定复用；重连、切换 direct/relay 和 daemon
重启后不无故改变地址。远程页面的并发资源请求不会被冷连接握手串行阻塞。

慢消费者不会造成无界缓冲；请求关闭、取消、断线和错误能传达给对应传输，
退出后释放资源，不影响其他独立请求。

Baseline 升级保留 v0.9.20 已经调优的交互表现与代理能力。一个大资源或慢消费者
不阻塞其他资源开始加载；连接复用不能变成等待新连接握手的串行队列。
新客户端连接旧 daemon、旧客户端连接新 daemon 时，已有 Viewer 代理仍可使用。
与上游协议编号冲突的适配不改变请求调度、流控参数或代理架构。
已认证主机的 Viewer 转发使用该主机当前的认证信息；新建转发连接、切换路由和
修改主机密码后仍能访问，不要求用户为 Viewer 再配置一份密码。

验收：外部浏览器页面含多个并发资源时可加载；慢读、取消其中一个请求、
断线重连和路由切换后行为正确。本条描述现有 HTTP 资源访问能力，
混合版本分别验证资源读取、并发、取消和重连。功能正确的同版本测试不能替代
与 v0.9.20 的响应表现对照。完整传输目标另见 VIEWER-05。
密码保护的主机分别验证 direct 与 relay，以及改密后本地入口的继续使用。

## VIEWER-03 — Android 外部浏览器持续访问

在 Android Chrome 打开结果后，客户端进入后台仍能按用户可见的前台服务约定
维持本地代理与连接。同一 host 复用稳定端口，返回 app 不重复创建代理。

验收：切到 Chrome、返回 app、断线重连和显式停止后连接状态可解释；
停止后释放所属资源，不遗留无法识别的后台服务。

## VIEWER-04 — 链接明确携带 host 身份

服务返回的成果链接携带实际 host 身份，形如 `paseo://h/<serverId>/view/...`。
聊天和报告能原样引用，由统一打开入口路由到对应 host。
桌面链接右键菜单可以复制原始 `paseo://` 地址，保留 host 身份与完整资源路径，
不需要先打开浏览器取得本机代理地址。
普通 `/view/...` 文件路径保留文件语义，不凭前缀猜成 Viewer。

验收：在两个 host 各有同名成果路径时，点击链接分别打开正确结果；
复制链接、跨页面打开与普通文件路径不会串用 host。

## VIEWER-05 — 固定传输规格的目标边界

范围：既有固定的目标规格，不构成 baseline bump 中替换已验证代理的授权。
用户于 2026-10-23 明确保留 v0.9.20 调优后的 Viewer，拒绝本次引入新的传输方案。
该目标与当前迁移分开评审；重新推进需先明确产品范围。规范内容由
[experiment-viewer-transport-spec.md](../refactors/experiment-viewer-transport-spec.md)
唯一维护，本条只登记其验收入口，不缩小或重写规格。

验收：升级记录逐项引用规格中的连接生命周期、half-close/reset、权限与可观测性
要求，列明已满足、缺失和未验证部分。现有 HTTP 资源访问成功不代表完整目标通过；
改变固定规格仍需用户明确批准。
