# Baseline bump 验收记录

每次 bump 在 `docs/contracts/reviews/<目标版本>.md` 保存一份完整记录，随候选提交提交。
该目录中的文件是版本证据，不新增长期产品要求。详细日志和截图可保存在关联 Works
记录，但这里保留结论、复现场景和可定位的证据；本机绝对路径不能是唯一证据。

## 版本记录

- [0.13.3：长历史、连接记录与持久数据校验修复](reviews/0.13.3.md)。
- [0.13.0-beta.1：会话、客户端、发行的本地 Web 预览](reviews/0.13.0-beta.1.md)。

## 记录格式

开头记录日期、旧产品 SHA、旧官方 tag/SHA、目标官方 tag/SHA、额外上游补丁、
候选源码 SHA、契约版本 SHA、Codex 版本和本次验证的平台。
若记录与候选代码同一提交，使用明确的源码父提交加工作树差异标识，完成后可由后续
记录或 PR 指向最终提交，不能留下自引用的虚构 SHA。

将 [契约入口](README.md) 及全部模块中的编号逐个列成行；目标、待决定和已被上游
满足的条目也保留。新条目同时进入当前候选和后续升级记录，旧条目退役保留决定。

| 契约 ID      | 实现归属                                   | 旧版状态                 | 候选结果                                           | 证据／复现场景               | 缺口与处理决定           |
| ------------ | ------------------------------------------ | ------------------------ | -------------------------------------------------- | ---------------------------- | ------------------------ |
| 每个编号一行 | 上游等价／上游加补充／fork／未交付／已退役 | 已验收／已知缺口／未验证 | 通过／失败／未验证／目标未交付／待决定／已批准退役 | 固定源码、具体检查或运行结果 | 跟踪入口、差异与用户决定 |

“上游等价”需要覆盖整个条目的预期行为，不能只比较功能名称、一个 RPC 或测试通过数。
将旧版用户可观察的子行为映射到当前契约与候选结果；位置、布局、适用平台、持久偏好、
操作入口和状态连续性均保留结论。整理契约时遗漏的旧行为仍属于迁移范围，恢复其定义后
重新判断候选。界面验收在相同场景下对照旧版与候选；“有同名按钮”只能证明入口存在。
源码审查可以证明静态事实；涉及运行时、故障恢复和平台行为的部分仍需对应场景证据。
未运行的场景保留“未验证”，不由类型检查或模型推断代替。

复用上游测试前，将断言对应到 fork 契约。测试输出是观察结果，预期值不是产品
要求；断言与契约冲突时，纠正过时预期或移除已退役场景，保留仍适用的边界验证。
记录冲突的契约编号、实际输出与处理，不能把该失败记作产品退化，也不能为通过
旧断言修改契约。关闭不适用的 workflow 不会使其中的失败变成通过。

自动化流程也属于迁移范围，逐项核对 RELEASE-02；一次专项验证不授权恢复上游
测试矩阵。过时的 workflow 配置、自检与文档随所属流程一并清理。

在表后记录：

- 每个旧 overlay 提交与最终差异的归属，以及未提交材料的保留位置。
- 移除的重复补丁、保留的临时上游修复及其清理条件。
- 格式、lint、typecheck 和受影响的定向验证结果；失败和环境限制明确列出。
- 未决项及完成条件：哪些是旧缺口、哪些是本次退化、哪些是尚未交付的目标。

## 新发现的问题

先将缺陷归属已有契约；只有预期行为尚未被覆盖时才新增或补全正向要求。契约定义
长期验收标准，issue 保存某个版本的失败、根因和修复过程，版本评审保存候选的实际
结果。三者引用同一个契约编号，不能用 issue 已登记或已关闭代替行为验收。

保留首次失败的版本、触发步骤和观察；尚未复现的因果关系标为待确认。修复在现有
验证入口中覆盖该失败场景，并检查对应要求的恢复和失败边界。未能稳定复现时，
记录已有证据和缺失条件，不把一次恢复或类型检查通过写成已修复。

会话历史性能按[测试项目](../session-history-performance.md)核对场景和预算；执行代码
与材料保留遵守该项目的约定。已有脚本只是执行缓存，不能代替当前要求或本次运行，
也不因验证需要而进入仓库。记录每项结果所需的简短结论即可。

Issue 关闭后保留契约和回归场景，后续 baseline bump 继续核对。发现契约遗漏时，
在当前评审补入编号及未验证状态，不等到下次升级才登记。

## 完成条件

每个编号都有明确结果和证据。声明 bump 已完成时，适用且已交付的行为通过验收，
新增退化已解决，差异已解释。已有缺口仍列出并关联跟踪记录，不能因原来就存在而
标为通过；如本次交付要接受某项失败或缩小范围，记录用户的具体决定。
目标未交付和待决定项不会冒充本次已完成能力，也不因换基线而自动承诺实施。

退役需保留用户决定；上游等价替代只改变实现归属，长期行为编号继续验收。
全部编号有行只说明覆盖完整，不等于行为全部通过。
