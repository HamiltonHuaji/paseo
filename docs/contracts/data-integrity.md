# 持久数据完整性契约

适用于客户端、桌面端和 daemon 的用户数据、身份与配置，以及 Paseo 修改的第三方
用户配置。连接列表的具体行为见 [CONNECTION-01](clients.md#connection-01--版本切换保留已配对主机)。
网络输入、权限和密钥的校验继续遵守各自的信任边界。

## DATA-01 — 读取不会销毁数据

存在但不能读取的数据与不存在的数据可区分。非法 JSON、不支持的版本、未知记录、
字段不匹配和 I/O 失败不会触发删除、身份重建，或用空集合、默认值覆盖原值。
错误指出受影响的存储对象；诊断不输出配对密钥、凭证或会话正文。

验收：分别注入上述失败，执行读取、启动和一次后续操作，核对原数据保留。
身份文件只在原本不存在时初始化；读取失败后恢复访问仍使用原身份。

## DATA-02 — 局部问题不删除其他记录

集合内某条记录不能被当前版本理解时，其余记录及无法理解的原内容保留。
正常编辑一项不会清空整个集合；用户明确删除的已识别项不会在重启后复活。
拒绝一次非法写入时，上一份有效保存仍在，写入失败不会被报告为成功。

验收：混合有效、未知和损坏记录，读后修改有效项、删除另一项并重新读取。
注入写入失败，确认保存内容和内存中的已保存状态一致，重试可成功。

## DATA-03 — 编辑保留未涉及的信息

读后保存和修改无关设置，不会删除未知字段、改变尚不支持的枚举值，或将界面使用的
默认值写回覆盖原值。用户明确修改某字段或重置相应数据时，其操作仍生效。
持久化数据保持一份；不为绕过已发布旧版的破坏性读取维护第二份兼容格式。

验收：加入未来字段、嵌套字段和枚举值，改变另一已知字段，重启后核对原内容；
再显式修改或删除已知内容，确认没有被无条件保留策略抵消。

## DATA-04 — 迁移与清理有有效的依据

支持的旧数据能按其版本恢复，不能在适用的迁移前被当前格式校验丢弃。
不支持的未来版本保留原值。迁移或读取失败不产生成功标记，也不会以空内存状态
为依据删除附件、引用对象或源配置。失败后修复环境仍可重试。

验收：旧版本、未来版本、迁移中途失败和附件读取失败分别核对；失败不清理源数据
或附件，不将部分结果标为完整迁移，不让后续自动保存覆盖原值。

## DATA-05 — 校验的后果与数据所有权一致

非法请求、无效权限和不可信执行内容仍被拒绝。拒绝使用一份输入不意味着有权删除
它。可从权威来源重建的缓存与用户唯一数据分别处理；缓存失效不波及权威数据。
显式删除、重置及有完整依据的生命周期清理保留原有语义。

验收：审查读取失败后的完整调用链，包含自动保存、迁移标记、附件清理、身份初始化
和第三方配置写回；同时验证原有权限与密钥校验没有因容错而放宽。

## 验证材料

每次 baseline bump 逐项记录结果和未满足项。故障注入脚本、样本和详细扫描清单可在
实验 storage 临时保存或复用，不作为仓库测试代码交付。已有测试中要求校验失败
就删除用户数据的断言应纠正，不能作为保留缺陷的理由。版本评审记录检查过的边界与
实际结果；搜索命中数不代表完整语义审计，类型检查不能证明数据未丢失。
