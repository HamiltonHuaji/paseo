# Skills 行为契约

仓库同步的完整行为和操作边界见[skill repository sync](../skill-repository-sync.md)。
以下编号是每次 baseline bump 的验收入口。

## SKILL-01 — 用户安装的 skills 保持用户所有

任一受管理的用户 skill root 已有同名手工目录时，目录与内容由用户所有。
Bundled skill 的安装、升级和清理保持用户内容，不覆盖、删除或跨 root 复制它。
用户显式卸载后，可以重新安装 bundled copy。

验收：不同 root 的同名目录、用户改过的 skill、daemon 升级与 bundled 版本变化，
都保留用户目录及选择。开发验证不会替换正在使用的全局 skills。

## SKILL-02 — 离线提交与客户端凭证中介

Daemon 没有 Git 凭证、客户端离线时，agent 仍能在订阅仓库本地编辑与提交，
获得 commit ID 和尚未上传的明确状态。获授权客户端上线后可获取或发布；
重试不会重复生成提交或误报远端成功。

认证范围绑定仓库、分支、操作与认证来源，Git 凭证留在客户端。
overwrite、fastforward、none 的行为遵守专题文档；本地分叉、远端强推或冲突
保留可恢复历史与可处理的状态，不更改用户的 skill 链接选择。

验收：离线提交后由客户端发布，另一 daemon 再按自己的订阅取得内容。
三种订阅模式、分叉和失败重试符合各自约定；无客户端权限时不会借用其他仓库凭证。

## SKILL-03 — 多设备计划与主机实际订阅一致

全局仓库目录、客户端代办权限和每 host 的订阅分别表达。
导入计划不自动授权使用凭证，未知或不可达 host 的成员仍保留。
稳定 ID、显式删除与冲突状态在多设备间有明确含义。

重连能读回 daemon 的实际订阅，不复活已删除项或用陈旧客户端配置静默覆盖修改。
加载、错误、空、未初始化、待应用与待发布可区分。

验收：客户端分别只连接不同 host，导入同一计划后各自处理可达部分；
离线修改、显式删除和并发配置修改都保留可处理结果。两个仓库含同名 skill 时，
各自 checkout 完整且用户选定链接不被同步覆盖。
