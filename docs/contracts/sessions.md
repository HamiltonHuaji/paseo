# 会话行为契约

适用范围以 Codex 为主。平台生命周期术语见[agent lifecycle](../agent-lifecycle.md)；
模型和存储上下文见[模型与项目存储](models-and-storage.md)。
以下验收描述用户可观察的结果，不指定历史数据库或状态机设计。

## CODEX-01 — 原生上下文分叉

原生 fork 创建可独立继续的 Codex 分支，保留所选完成边界及之前的原生上下文，
包括工具上下文和有效指令。新会话继承来源的有效模型、推理档位、service tier、
模式、工具与工作目录设置；用户明确修改的选项除外。

用户能区分原生分叉与聊天文本复制。来源会话和工作区文件保持原状。
当前未完成边界有明确拒绝原因；来源仍在工作时，合法的较早完成边界可用。
边界定位不受客户端已加载页数或消息展示方式影响。
只读历史的缓存回收、重建和关闭其他分支不使仍存在的完成边界失效。
原生 fork 按 provider 消息身份定位，由 provider 的当前历史决定所属 turn、完成
状态与截断点，不由显示缓存推断。原生消息 ID 可用时，不依赖时间线游标；兼容
仅带游标的旧请求时，先在该缓存版本内转换为原生 ID。消息已被 rewind 移除或
只有失效游标时，拒绝操作，不能沿用旧行号。

验收：从含工具调用的长会话的较早完成 turn 分叉，原生历史止于所选边界，
新分支重启后仍可继续；来源继续自己的执行。未完成边界不会产生冒充成功的会话。
功能可用性与连接主机的能力一致，旧客户端缓存缺少可选字段不会误判能力。
从同一回复 fork、关闭新分支，再从该回复 fork；覆盖期间浏览其他会话导致来源
缓存回收、来源历史只有部分页，以及 rewind 后所选消息已不在当前分支的情况。

## SESSION-02 — 非破坏性的 rewind

Rewind 保持 Paseo 会话身份，将当前对话移到所选用户 turn 之前的原生分支；
所选 turn 及之后内容不属于新当前分支。原分支仍可恢复，工作区文件保持原状，
界面准确说明回退范围。配置连续性与 CODEX-01 相同。

当前原生身份、可见历史和持久分叉关系描述同一次操作。操作中断或部分失败后，
用户得到可恢复且可解释的状态；重启不能静默恢复到另一个分支，也不能把旧历史
显示成新分支的完整历史。

验收：成功后重启、连续 rewind、长历史中的旧边界均得到正确分支。
在原生分支已创建而历史读取失败、持久化失败或连接断开时，重新打开仍能辨认
已完成的切换或尚未完成的操作，原会话数据可恢复。

## SESSION-03 — 可追溯且独立的会话关系

Paseo 会话 ID、provider 分支 ID、provider 会话树身份、托管 agent 的管理父子关系、
provider 自有 child，以及用户创建的分叉关系各有明确含义。
管理关系决定的生命周期行为沿用 [agent lifecycle](../agent-lifecycle.md)；
对话分叉关系本身不产生管理或归档级联。

原生 fork、文本复制和 rewind 可区分。关系可追溯到来源主机、稳定 Paseo 会话、
来源和结果的原生身份、操作类型及边界。Rewind 后，旧原生身份仍能解析回其来源
Paseo 会话；来源或后代重复 rewind 都不覆盖先前关系，也不把替换的原生分支画成
新增的 Paseo 会话。关系以身份区分，重命名或同名不改变归属。

升级前已存在的分叉也属于恢复范围，包括未显式保存来源、只有旧关系字段，以及已被
标成未知的记录。能由已保存的关系、原生祖先链和身份历史确定来源时，恢复其可用的
来源引用；不能仅因新版主机、操作或边界字段缺失就让关系消失。可确定当前来源会话
与能否还原全部历史操作信息分别判断，未获证实的信息保持未知。

原生文件可能来自其他主机，原生 ID 相同本身不证明本地主机来源。实际缺失、证据冲突
或无法消除的多候选保持可辨认，不猜父会话；后续取得证据时可以重新解析，未知状态
不成为永久跳过恢复的理由。来源位于其他工作区或已归档，不等于关系不存在。
恢复只读已有记录，不启动会话 writer，也不要求用户重新 fork 才能补齐旧关系。

验收：A fork 出 B、C，B 再 fork 出 D；A、B 分别多次 rewind 后升级、重启，
仍得到 A→B、A→C、B→D，所有节点保持稳定 Paseo 身份。分别覆盖旧字段、原生历史
可恢复但无显式来源、曾标未知、同名会话，以及跨工作区和归档来源。另以外来文件、
来源缺失、重复导入和冲突证据检查误连边界。关闭或归档一条分支不会仅因血缘影响
独立分支。Canvas 如何呈现这些关系遵守 SESSION-01。

### 已知恢复措施

Baseline bump 必须保留以下证据读取与恢复能力。这里记录已知的恢复路径，避免每次
升级重新研究；文件、字段或内部接口变化时迁移其对应能力，不要求沿用原来的实现。
这些证据不必全部齐全，按下方判定表处理已有组合。

| 证据           | 已知读取位置                                                                                                                    | 用途与边界                                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Paseo 会话登记 | agent record 的 `id`、`provider`、`persistence.sessionId`                                                                       | 建立当前原生身份到稳定 Paseo 身份的映射；查找范围包含同一 daemon 的其他工作区与归档记录                                                                            |
| 创建回执       | `$PASEO_HOME/creations/*.json` 的 `snapshot.agent.id` 与 `snapshot.agent.persistence.sessionId`                                 | 取得会话最初绑定的原生 ID；当前 handle 被 rewind 替换后仍可定位原分支                                                                                              |
| 历史身份与操作 | `providerSessionIds`、`sessionLineage`，以及 `persistence.metadata.branchOperations`                                            | 保留旧原生 ID；`rewind` 的 source/result 都归同一 Paseo 会话，普通 fork 的 source 不归新会话                                                                       |
| 已存来源       | `forkedFrom` 与 `sessionLineage` 的非 rewind 来源记录                                                                           | 显式操作可指明来源 host、Paseo ID 和原生边界；旧记录可能只有 `forkedFrom.agentId`，不能要求其已具备新字段                                                          |
| Codex 原生父链 | 有效 Codex home 的 `sessions`、`archived_sessions` 中 rollout JSONL 的 `session_meta.payload.id`、`forked_from_id`、`timestamp` | `forked_from_id` 是直接原生父分支；无需启动 Codex 会话或比对完整聊天正文。扫描包含 provider 配置的 home 及历史 handle 的 `paseoCodexHome`，不能只查默认 `~/.codex` |

按以下顺序恢复：

1. 在同一 provider 身份范围内，为每个 Paseo 会话收集当前 ID、创建回执中的初始 ID、
   已保留的原生别名、rewind 操作的 source/result。反向索引保留一个原生 ID 的全部
   Paseo 候选，不能以读取顺序覆盖重复导入。其他工作区和归档不从索引中排除。
2. 先还原同一 Paseo 会话内的 rewind 链。从当前原生分支沿父链回溯，到初始 ID 或
   已知历史身份为止；两端均已归本会话、且中间没有冲突归属的连续片段可补入其
   原生别名。缺少这样的边界时，不把所有祖先都吞并到当前会话；遇到其他所有者或
   多候选时保留冲突。
3. 从当前分支回溯，跳过已确认属于本会话的 rewind 片段。第一个离开本会话身份集合
   的直接原生父 ID，是待解析的来源；通过反向索引查找其 Paseo 所有者。这一步同样
   用于从未保存 `forkedFrom` 的会话。直接父 ID 无法映射时保留它，不能跳过它、把
   更远的已知祖先冒充直接父会话。
4. 将结果与已存来源按下表合并。已标 `unknown-host`、`missing` 或 `ambiguous` 的
   旧记录也重新评估，不能因已有非 rewind 条目就跳过。保存已确认的历史身份和
   来源依据，重复恢复不生成重复操作，不清空本轮未能读取的既有证据。

| 证据组合                                                                                     | 应得到的结果                                                                                                 |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 显式 Paseo 操作记录指明来源 host／稳定会话 ID                                                | 保留这个明确来源；多一个相同原生 ID 的导入副本不会改写用户当时选择的来源。明确外地主机来源不被本地同 ID 覆盖 |
| 旧 `forkedFrom.agentId = A`，恢复出的直接原生父唯一归 A，且无相反的显式来源记录              | 确认 A→当前会话；旧记录缺少 host、operation 或边界不阻止使用这条关系                                         |
| 无已存来源，直接原生父唯一映射到已登记的 A，当前会话的原生归属及 rewind 边界明确，无冲突记录 | 恢复 A→当前会话，标明来自原生历史；不要求用户先在 Paseo 中执行一次新 fork                                    |
| 只有父原生 ID，未找到 Paseo 所有者                                                           | 保留原生来源，显示来源未定位；不能凭标题、目录或创建时间挑一个父会话                                         |
| 多个所有者，且无指明稳定来源的操作记录；或旧推断与原生证据冲突                               | 保留候选或冲突，不按最新、最早、同工作区或列表第一项消歧                                                     |

上表恢复的是当前能定位的来源会话引用。唯一的本地所有者可以作为对应原生分支的
可访问入口，但不能据此声称历史 fork 必定发生在这台主机，也不能补造操作类型或
消息边界。已有的显式远端来源仍保持远端。仅凭时间接近、同名、相同 cwd、聊天文本
前缀或原生文件恰好在本机，不足以建立 Paseo 父子关系。

固定的 rewind 复核例：原生父链 `b2 → b1 → b0 → a1 → a0` 中，创建回执把
`a0` 归 A、`b0` 归 B，当前 handle 分别为 `a2`、`b2`，另有 `a2 → a1 → a0`。
没有冲突归属时，A 拥有 `a0/a1/a2`，B 拥有 `b0/b1/b2`；因此 `b0` 的父 `a1`
解析为 A，Canvas 只有 A→B，不出现六张原生分支卡，也不因 A 当前已是 `a2` 而断边。
删去显式 `forkedFrom`、换成已标未知的旧记录、再重复恢复，结果仍应相同。

当前读取入口为 [Codex lineage reader](../../packages/server/src/server/agent/providers/codex/session-lineage.ts)，
身份归并与关系恢复入口为 [session lineage](../../packages/server/src/server/agent/session-lineage.ts)。
这些是查找入口，不代表实现已满足上述全部要求；版本缺口见升级评审。

## AGENT-01 — 真实调用者与操作归属

受管 agent 的 CLI、工具和子进程获得实际 Paseo agent 身份；工具归属来自运行上下文，
不依赖模型手填 ID。人工 CLI 没有 agent 身份仍可使用。跨 host 操作能区分来源与
目标身份，不把来源 host 的 ID 冒充为目标 host 的受管 agent。

Provider 自有 child 与 Paseo 受管 agent 的身份区别可见；共享父 runtime 的调用不能
凭空登记成一个新的受管 agent。Works 的自动参与与长期会话关联见
[WORKS-01](works.md#works-01--独立工作对象与组件语义)。

验收：agent 经 MCP 和 CLI 修改工作记录都归属实际调用者；人工操作不伪造参与者；
切换目标 host 后来源仍可解释。记录参与不会自动授权新建、唤醒或委派 agent。

## MCP-01 — 中断与恢复后的工具可用性

有效配置和授权未改变时，手动停止、继续对话、关闭后恢复或连接重建不会使已配置的
MCP 工具静默消失。恢复交互后，agent 能发现并调用这些工具；保留配置字段或旧工具
调用历史不等于当前工具可用。原生 fork 和 rewind 的工具继承遵守 CODEX-01、SESSION-02，
也须以实际发现和调用验收。

初始化中断、服务暂时不可达或工具发现失败有可见原因和可重试入口，不能被当作永久
未配置或空工具集。显式禁用、撤销授权和服务实际不可用仍按真实状态处理，不伪造能力。
仅浏览历史不为验证工具而恢复交互 writer，遵守 SESSION-04。

验收：比较新会话、正常下一 turn、手动停止后继续、fork、rewind、关闭后恢复与连接重建时的工具
发现和实际调用。覆盖初始化尚未完成时停止、暂时连接失败后重试，以及主动禁用或
撤权；每个结果能区分就绪、失败和未配置。偶然在下一 turn 恢复不构成修复证据。

## CODEX-02 — 单写者恢复与会话连续性

同一原生分支同时最多有一个交互 writer。Reload、恢复、配置切换或 rewind 遇到
尚未确认结束的旧执行时，不启动竞争 writer。失败后保留 Paseo ID、名称、关系、
workspace、历史和可重试入口，并显示具体失败原因。

验收：连续 reload、关闭失败、恢复失败和取消超时都不会形成双写或丢失会话记录。
可安全重试的失败能够重试；仍在执行的旧 turn 不被伪装为已停止。

待决定：旧版曾自动恢复旧配置；当前上游的失败结果是保留 closed 会话并允许重试。
两者都不等于“配置切换成功”。自动回退是否重新成为交付要求仍需产品决定；
升级记录必须写明候选版本的实际结果。

## CODEX-03 — 执行状态有真实依据

完成、取消、失败的根 turn 不再留下仍在执行的根工具动画或等待提示。
真实后台 child 保留自身生命周期，父 turn 结束不代表 child 完成。
Codex 的失败终态（包括 `errored`）对用户表现为失败，不表现为 running。

历史中的 started/interacted 只能证明过去的活动，不能证明当前仍存活或已经完成。
重连和历史重放后，状态表达可用的执行证据；证据不足时不会伪造活性或成功。

验收：正常完成、取消、断流缺少末端工具事件、失败 child、父结束而 child
继续运行、历史重放均得到可解释状态。中断 wait 的动画停止，真实 child 仍可检查。

## CODEX-04 — 可恢复的异步问题

异步问题作为会话内容保留，agent 可在用户回答前继续工作；阻塞式权限请求仍有
独立生命周期。回答保留对应问题的来源，多个问题、自由文本和后续 turn 不会串答。
等待用户确认的计划审批不因生成计划的根 turn 结束而被取消，用户仍能处理该审批。

验收：重启后待答问题仍在；提交成功后不会再次出现为未答。
发送失败或 active turn 已变化时保留回答并允许重试，不误清其他问题或权限。
Rewind 后只保留当前分支有效的问题与回答。关联语义不依赖某个固定协议字段名。

## CODEX-05 — 导入与显式副本

用户能按 provider 和项目找到可导入会话，完整浏览分页结果，并辨认已导入记录。
通过符号链接访问同一目录仍能找到其会话；过滤后空页仍可继续读取后续匹配结果。
失败有具体原因和重试入口；并发重复导入不产生无法辨认的重复受管会话。

原生 writer 被占用时，支持的 provider 提供显式“导入副本”，得到可独立继续的
原生分支，来源保持原状；不支持时明确说明能力边界。

验收：占用中的 Codex 会话可显式复制后继续；普通导入不会偷偷变成副本。
连接或历史读取失败不遗留竞争 runtime；重试和重复导入保留正确关系。

## CODEX-06 — 内容传输完整，诊断有边界

合法消息中的中文、多字节字符、U+2028/U+2029 和跨 chunk 内容完整到达用户。
单个无效帧可诊断，后续有效消息仍可处理；常规警告不复制完整会话正文或坏帧载荷。

验收：上述字符和分块边界不会拆坏消息；异常日志提供定位所需的错误和有限元信息，
不包含整段 prompt、工具结果或凭证内容。

## SESSION-01 — 会话 Canvas

工作区提供位于 Works 入口旁的会话 Canvas 入口，以稳定 Paseo 身份展示会话卡片和
分叉边。用户用一个来源会话维持项目总体上下文，再 fork 出专注具体功能的分支；
Canvas 应能沿这条关系进入细节、辨认同级分支并返回来源上下文。关系判定遵守
SESSION-03，空间阅读质量遵守 [Canvas 契约](canvas.md)。

提供按分叉关系组织的排列：同一来源的分支及其后代聚在可连续阅读的区域，独立
会话群可区分，兄弟不会看起来互为祖先。关系排列不因全局活动时间交错而把同一
分支拆散；长链不要求每深入一级就横移一整张卡。具体排列算法不在本契约中固定。

保留按创建、fork、最后用户输入、最后回复排列的时间视图。事件按所选方向从上到下
在每棵会话树内部紧凑排序，不逐行横排，也不按实际时长留下巨大空白。独立树作为
完整区域紧凑排列，不因各树事件交错而穿插；单独会话也不集中拉成一条长队。
缺少相应事件时不伪造时间；按分叉时间看时，无分叉事件的根作为本树的来源入口，
不被放到所有树之后。时间视图保留可辨认的代际缩进和分叉通道；不为缩小外接矩形
而把不同层级压进近乎重叠的列。独立会话规整排列，避免看起来像另一条来源链。
同一输入的结果可复现。关系排列表达分支层级，时间排列表达树内事件顺序。

来源在其他工作区、已归档或被筛选隐藏时，仍能辨认来源及其不可见原因；可访问的
来源可以打开或定位。不能把这些分支默默表现为无来源会话，也不画指向隐藏卡片的
悬空边。未知或歧义来源按实际证据呈现，不能用确定的父边冒充。

刷新活动、恢复关系和新增会话不覆盖已有手动布局。关系排列下新增分支靠近所属
会话群，用户仍可显式重排。打开卡片详情可阅读和继续完整会话、重命名，并保持
Canvas 阅读位置；关闭详情不停止会话。仅浏览时遵守 SESSION-04。

验收同时使用 SESSION-03 的拓扑和真实积累的多分支、多代会话图：在正常文字大小
下找到某个功能分支的来源、比较其兄弟、沿祖先返回总体上下文，并打开详情后回到
原处。覆盖同名、跨工作区、归档、缺失来源与独立会话混排；核对四种时间排列、
新分支位置、重排可复现及手动布局保留。边数正确或三节点演示不能代替阅读验收。

## SESSION-04 — 历史浏览不改变执行与归档

只查看历史不取得交互 writer，不启动会话执行，不改变 agent 或 workspace 的归档。
恢复交互是独立、明确的操作。历史获取失败与会话不存在、已完成或已删除可区分，
已保存的历史不因读取失败被抹掉。

验收：浏览归档、closed 和长历史会话后，其执行和归档状态保持一致；provider
不可用时显示真实读取状态。性能与连接连续性另按 SESSION-05–07 验收。

## SESSION-05 — 长历史的交互性能

打开会话后，最近消息在[性能测试项目](../session-history-performance.md)的首屏预算内
可用；继续浏览、重复打开和重连后的读取满足各自预算。历史总量增长不会使只查看
最近一小段的操作退化为分钟级等待。首次冷读取也属于要求，预热后的结果不能代替它。

翻页、重试和重连不会使等待时间或资源消耗随重复次数持续累积。读取结果保留顺序、
消息身份、完整性与可继续读取的位置；较早内容仍可取得，按消息 fork 与 rewind
不因当前加载范围而改变边界。

验收：执行测试项目 HP-01–04、HP-07；分别检查首次内容可用、后续读取和完整读取
完成时间。返回加载提示、空成功或延长超时不计作首屏内容可用。预算不规定 provider
API、分页方向、缓存、数据库、后台任务或传输实现。

## SESSION-06 — 客户端节制请求，读取保持兼容

新版 app、SDK 和 CLI 根据当前操作需要取得历史。查看最近内容、有限条数日志、
恢复连接或保持订阅时，请求和传输量随实际需要及有限预取变化，不因历史总量增长而
自动读取全部历史。并发调用、超时和重试不造成持续放大的请求负载。显式请求完整
历史仍得到完整结果，传输可分批进行，不能依赖单条消息承载全部历史。

在支持的版本组合中，旧客户端已支持的合法历史请求继续按原语义完成，包括较大
范围、未指定上限以及旧版的完整读取请求。新客户端的节制行为不成为 daemon 接受
旧请求的前提；内部页面、缓冲或调度阈值不能把原本合法的操作变成必须升级、改写
请求或缩小范围后才可执行的操作。

验收：执行 HP-05–06。新客户端主动节制，旧客户端常规读取保持兼容；不静默截断、
不伪报完成。已实测并经用户确认的旧客户端／既有 relay 单消息硬上限，可把超出上限
的完整读取列为旧端已知限制；记录版本、大小和影响，不能据此拒绝原本能完成的请求。
新端完整读取必须分批成功，旧端超限失败不应拖垮无关连接。该例外不涵盖新引入的
内部阈值或未验证的能力边界，仍遵守[协议兼容约定](../protocol-compatibility.md)。

## SESSION-07 — 历史负载下的服务连续性

大历史读取、完整日志输出、多个读者和客户端反复断线期间，daemon 的元信息查询、
其他会话读取与心跳继续满足响应预算。历史工作不会造成无关请求超时、非预期断连
或重连循环。正常读取最终完成，失败可辨认且可重试；连接成功与历史就绪分别表达。

断线与取消不使其他读者失去结果，重新连接后能够继续取得正确内容。过期读取不会
覆盖更新后的历史；慢读者不会让其他连接持续排队。相同负载反复执行后，未完成工作、
进程和内存占用不会随次数无界增长；取消和正常关闭在测试预算内收敛。

验收：执行 HP-03–04、HP-06–08。区分主动断线、真实网络故障与历史负载诱发的断线；
分别检查结果、延迟和资源收敛。只读与存储语义继续遵守 SESSION-04、STORAGE-01。

## SESSION-08 — 客户端历史收敛与顺序

已经确认的新历史不会被迟到的旧读取覆盖，实时新增内容不会因旧快照晚到而消失。
这一要求同时适用于可见内容、会话元信息和持久缓存；旧 tail、较早分页和增量响应
都不能把 rewind 前的内容重新带回来。同一历史代际内，已确认的覆盖范围不后退；
代际标识只表达身份，不按字符串大小或首条事件序号判断先后。

rewind、历史重建、重连或回到前台后，打开的会话最终收敛到 daemon 的当前历史。
期间可继续显示缓存，但同步状态与操作边界不会把缓存误称为当前历史。首次恢复
失败可自动重试，也能由用户重试；即使之后没有新消息，也不会永久停留在旧历史。
恢复途中收到的新事件不会被遗漏，已经淘汰的代际事件不会使会话退回旧状态。

同步仍按用户打开的会话和阅读窗口发生，沿用 SESSION-05/06 的负载与兼容要求；
会话 Canvas 的元信息展示不触发全量正文读取。

验收：执行 HP-09，交错真实客户端读取、替换通知与流事件，核对内存和持久缓存，
并验证无新消息时的失败恢复、前后台切换和重连。不得只验证单次成功读取。

## UPSTREAM-01 — 增量同步保留会话

重连和增量目录更新后，既有会话仍在正确的项目与工作区中可见。
缺少可选 placement 信息不会使已知会话从目录中消失。

验收：旧复现场景在增量 catch-up 后可直接打开会话，无需等待全量快照。
上游满足后继续使用其行为，验收编号保留作为回归入口。
