# 会话历史性能测试项目

本项目验收 [SESSION-05–07](contracts/sessions.md#session-05--长历史的交互性能)，
同时检查 SESSION-04 的只读边界及原有消息、fork、rewind 语义。
它定义输入、操作、测量与通过条件，不规定修复方案。当前范围是 daemon、SDK、CLI
和真实 relay；不要求客户端 UI 自动化，也不以协议测试代替 UI 体验验收。

## 执行材料

契约和本说明进入仓库。历史副本、临时测试代码、探针、配置与运行输出放在仓库外的
实验 storage，均不提交。已有脚本是允许复用、修改或丢弃的执行缓存；运行前按本说明
核对覆盖范围。脚本能运行、以前通过或缓存仍在，都不代表当前候选满足要求。

不要求永久保存完整日志、正文或旧脚本。每次验收保留简短结论：版本、环境、样本规模、
各 HP 项目的通过／失败／未验证、关键耗时和剩余问题即可。即使执行缓存丢失，也能
根据本说明重新组织测试；缺少相应数据或运行条件时如实标记未验证。

每次从历史副本建立独立运行目录，同时隔离 Paseo 与 provider 的状态、端口和进程。
包含 provider 实际读取所需的数据库、归档与元信息，不能只凭 JSONL 大小认定副本完整。
不改写用户的原历史，不重启生产 daemon。连接、查询产生诊断日志仍属于逻辑只读；
恢复 writer、提交新 turn、fork、rewind 单列为语义校验，只在可丢弃副本上进行。

已有执行缓存可从实验 `exp_e2b5f401`（真实 Codex 历史 daemon 只读访问与冷恢复验证）
寻找。它不是运行前提，也不是永久保存要求。样本正文和凭证不进入仓库。

## 输入与环境

使用真实 provider 和真实发行包／明确源码版本启动 daemon。SDK、CLI 与 relay 各自
记录实际版本；兼容性测试使用旧版实际解码器与行为，不能用新版 SDK 假报旧版本。

| 样本        | 必要特征                                                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S：短历史   | 少于 500 个可见条目，包含用户消息、回复与工具调用；同时作为无关会话的响应对照                                                                                                      |
| L：长历史   | 优先使用 Paseo agent `2f624a7a-e35e-4a0d-bf93-5f217326f4e9` 的副本；2026-10-24 副本约 48 MB rollout，投影约 22,500 条，旧响应约 126 MB。替代样本具有同量级字节数、条目数与工具内容 |
| G：增长历史 | 总条目与正文规模至少为 L 的四倍，最近窗口内容规模与 L 相近；由 provider 能正常识别的有效历史组成，不能简单拼接出重复 ID 或错误分支                                                 |
| B：边界内容 | 中文、多字节字符、很长的单条消息／工具结果、跨读取边界的工具生命周期，以及有效 child 历史                                                                                          |

记录实际条目、字节和最近窗口大小；上表的近似值不是精确断言或协议上限。L 的来源
数据需要 provider 数据库配合读取，JSONL 行数不等于可见条目数。G、B 不得通过删除
真实内容、提前裁剪输出或更换成空工具调用来满足预算。

参考环境为同一台机器上的隔离 daemon、客户端和本地真实加密 relay，磁盘与 CPU 无
竞争性重负载。记录硬件、Node/provider 版本及资源限制；旧版和候选使用同等条件。
直连和 relay 分别验收。真实远程链路可另测 RTT／带宽与总耗时，不能用 WAN 抖动解释
本地超时，也不能把本地 relay 结果当作移动网络验证。

## 计时与预算

“冷”指新 daemon 和新 provider reader、没有该样本的派生历史缓存；操作系统页缓存
是否仍热需注明，不清理整台共享机器的系统缓存。“热”指已成功打开过该历史。
网络握手单独计时；历史计时从合法请求提交开始，至调用方收到并解析出完整所需内容。
排队、provider 启动／读取、映射、序列化及传输均算入，不在内部某阶段才开始计时。
若实现把该历史的准备前移到 daemon 启动或连接阶段，这部分等待也计入冷读取，
不能通过提前预热绕过首屏预算。

一次首屏读取指最近 40–50 个可见条目或等价可用窗口；不是空响应、确认通知或加载提示。
完整读取计时至全部请求内容可用、结束状态正确。CLI 同时测首个有效输出和完整结束。

以下是本轮提出的初始本地验收目标，不是已有性能测量的结论。预算的修改按契约变更
评审，不能为使某次 bump 通过而临时放宽。

| 操作                                       | 本地验收目标                                                    | 采样                                              |
| ------------------------------------------ | --------------------------------------------------------------- | ------------------------------------------------- |
| L、G 冷读取最近窗口                        | 每次 ≤ 5 秒                                                     | 各 3 次独立冷启动                                 |
| 热读取、较早一页、重新连接后的最近窗口     | p95 ≤ 1 秒，单次 ≤ 3 秒                                         | 每类至少 20 次；重连耗时从握手完成计              |
| 历史负载期间查询元信息、读取 S、应用层心跳 | p95 ≤ 1 秒，单次 ≤ 3 秒；无超时或非预期断连                     | 覆盖整段负载，至少 20 次                          |
| L 完整读取                                 | 新端 ≤ 60 秒，首个有效窗口 ≤ 5 秒；旧端在其已确认传输能力内成功 | 冷／热各一次，直连与 relay 分开                   |
| 读者离开后的工作收敛、正常关闭被测 daemon  | ≤ 10 秒结束无人需要的在途工作；正常关闭无需强杀                 | HP-03、HP-08 各检查；允许保留有界的可复用空闲状态 |

完整读取的传输量可以随请求内容增长。G 的完整读取单列总量和速率；它的最近窗口、
补页和无关请求仍使用上表交互预算。对 G 不套用 L 的完整读取总时长预算。
较大单条内容的完整传输时间按字节量单列；返回完整正文的可用入口不等于全文已取得。

旧 daemon 的已有性能缺口单列，不要求新客户端消除旧实现的内部耗时；但新客户端
不得额外放大请求或损坏其既有结果。新版 daemon 与受支持的旧客户端组合仍验收旧请求
的完成和连接连续性，不能用新接口的成功替代旧接口测试。

## 判定

性能以调用方实际收到的有效内容和无关请求的响应判定。provider RPC 数量、缓存命中、
事件循环停顿、RSS 和读取字节数可用于定位原因，不规定必须只发一次 RPC、必须缓存
或必须使用某种存储。固定输入重复运行后，资源可以稳定在有界平台，不能逐轮累积
未结束工作、进程或内存。记录峰值和恢复后的状态，不能仅看最后一次成功请求。

正常请求应成功完成。只有故障注入项目才以可解释失败和可恢复为预期；不能把实现
自己的响应上限包装成注入故障。旧端完整读取的已确认硬上限按 SESSION-06 单列
已知限制，常规读取继续验收；新端不能借用该例外。未确认的新边界仍须报告并评审。

同一场景的旧版也失败，说明它是既有缺口，不代表候选通过。provider 自身的正常冷
读取耗时计入用户等待；说明瓶颈所在不能替代满足预算。特殊故障注入的等待与正常
路径分开报告，不用永久“加载中”掩盖超时。

运行结论回到[baseline 验收记录](contracts/baseline-review.md)中的对应编号。没有运行
的组合写未验证；本说明和脚本的存在不表示性能修复已经交付。
